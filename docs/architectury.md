# OnlineStore ақпараттық жүйесінің үш деңгейлі архитектуралық диаграммасының сипаттамасы

### 1. Диаграмманың мақсаты

OnlineStore — интернет арқылы киім өнімдерін сатуға, тапсырыстарды қабылдауға, төлемдерді тіркеуге, қоймадағы тауар қорын бақылауға және жеткізуді басқаруға арналған ақпараттық жүйе.

Архитектуралық диаграмманың мақсаты — жүйенің негізгі компоненттерін, олардың атқаратын міндеттерін және өзара ақпарат алмасу тәртібін көрсету.

OnlineStore ақпараттық жүйесі үш деңгейлі архитектура (Three-Tier Architecture) негізінде жобаланған:

1. Презентация деңгейі (Presentation Layer).
2. Қолданбалы логика деңгейі (Business Logic Layer).
3. Деректер деңгейі (Data Layer).

Бұл архитектура жүйенің функционалдық бөліктерін бір-бірінен ажыратып, олардың өзара байланысын ұйымдастыруға мүмкіндік береді.

### 2. Жүйенің пайдаланушылары

OnlineStore ақпараттық жүйесінде бес негізгі пайдаланушы қарастырылған.

**Клиент** — интернет-дүкендегі тауарларды қарап, қажетті киімдерді іздейді, тапсырыс қалыптастырады және төлем әдісін таңдайды. Сонымен қатар тапсырыс пен жеткізу мәртебесін бақылай алады.

**Жүйе әкімшісі** — пайдаланушыларды және жүйенің негізгі ақпаратын басқарады. Тауарлар, санаттар және қызметкерлерге қатысты басқару операцияларын орындайды.

**Менеджер** — тапсырыстарды өңдейді, олардың орындалуын бақылайды және дүкен қызметін ұйымдастыруға қатысады.

**Қойма қызметкері** — қоймадағы тауарлардың қолжетімді санын тексереді, тапсырыстарды жинайды және тауар қорына қатысты ақпаратпен жұмыс істейді.

**Курьер** — тапсырысты клиентке жеткізеді және жеткізу мәртебесін жаңартады. Жеткізу аяқталғаннан кейін тиісті ақпарат жүйеде тіркеледі.

### 3. Презентация деңгейі (Presentation Layer)

Презентация деңгейі пайдаланушылардың жүйемен өзара әрекеттесуін қамтамасыз етеді.

Бұл деңгейдің негізгі компоненті — пайдаланушы интерфейсі (User Interface — UI).

Интерфейс құрамына келесі элементтер кіреді:

- Жүйеге кіру және тіркелу формалары.
- Тауарлар каталогы және іздеу өрісі.
- Тапсырыс қалыптастыру беті.
- Төлем әдісін таңдау формасы.
- Әкімші мен менеджердің басқару панелі.
- Қойма қызметкерінің жұмыс интерфейсі.
- Курьердің жеткізу мәртебесін жаңарту интерфейсі.

Пайдаланушы интерфейсі енгізілген ақпаратты қолданбалы логика деңгейіне жібереді және өңдеу нәтижелерін пайдаланушыға көрсетеді.

### 4. Қолданбалы логика деңгейі (Business Logic Layer)

Қолданбалы логика деңгейі жүйенің негізгі операцияларын орындауға жауап береді.

Бұл деңгейде алты негізгі модуль қарастырылған.

**Авторизация модулі.** Пайдаланушылардың жүйеге кіруін тексеруге және олардың рөлдері бойынша қол жеткізу құқықтарын анықтауға арналған.

**Каталог модулі.** Киім өнімдерін қарау, іздеу, санаттарға бөлу және тауарлар туралы ақпаратты басқару операцияларын орындайды.

**Тапсырыстарды басқару модулі.** Клиенттердің тапсырыстарын қабылдайды, тіркейді, өңдейді және олардың орындалу мәртебесін жаңартады.

**Төлемдерді басқару модулі.** Kaspi карта және Halyk карта сияқты төлем әдістерін тіркейді. Төлем сомасын, әдісін және мәртебесін өңдейді.

**Қойманы басқару модулі.** Қоймадағы тауарлардың санын тексереді, тапсырысқа қажетті өнімдердің қолжетімділігін анықтайды және тапсырысты жинау операцияларын ұйымдастырады.

**Жеткізуді басқару модулі.** Курьер туралы ақпаратты, жеткізу мәртебесін және тапсырыстың жеткізілген уақытын өңдеуге жауап береді.

Барлық модульдер дерекқормен деректерге қол жеткізу компоненті арқылы байланысады.

### 5. Деректер деңгейі (Data Layer)

Деректер деңгейі жүйедегі барлық ақпаратты сақтауға және өңдеуге арналған.

Бұл деңгей екі негізгі компоненттен тұрады:

**Деректерге қол жеткізу компоненті (DAL).** Қолданбалы логика деңгейінен келетін сұраныстарды қабылдап, SQL операцияларын орындайды. Дерекқордан қажетті ақпаратты оқып, оны қолданбалы логикаға қайтарады.

**Microsoft SQL Server дерекқоры.** OnlineStore ақпараттық жүйесіндегі деректерді сақтайды.

Берілген SQL құрылымы бойынша OnlineStore дерекқорында сегіз кесте бар:

1. Client — клиенттер туралы ақпарат.
2. Staff — әкімші және менеджер туралы мәліметтер.
3. Category — киім санаттары.
4. Product — тауарлар және олардың сипаттамалары.
5. Warehouse — қоймалар туралы ақпарат.
6. CartPayment — төлем туралы ақпарат.
7. Order — тапсырыстар.
8. Delivery — жеткізу туралы мәліметтер.

Кестелер арасында сыртқы кілттер арқылы байланыстар орнатылған. Мысалы, Product кестесі Category және Warehouse кестелерімен байланысады, ал Delivery кестесі Order кестесімен байланысқан.

### 6. Компоненттер арасындағы бағытталған байланыстар

Архитектуралық диаграммада ақпарат алмасу бағытталған жебелер арқылы бейнеленген.

Сұраныс бағыты:

Пайдаланушы → Пайдаланушы интерфейсі → Қолданбалы логика → DAL → SQL Server дерекқоры.

Жауап бағыты:

SQL Server дерекқоры → DAL → Қолданбалы логика → Пайдаланушы интерфейсі → Пайдаланушы.

Мысалы, қойма қызметкері тауардың қалдығын тексеру үшін интерфейс арқылы сұраныс жібереді. Сұраныс қойманы басқару модуліне түседі. Модуль DAL арқылы Product кестесінен қажетті ақпаратты алады. Нәтиже кері бағытта қайтарылып, қойма қызметкерінің интерфейсінде көрсетіледі.

Курьер жеткізу мәртебесін өзгерткен кезде сұраныс жеткізу модулі арқылы өңделіп, Delivery кестесіндегі тиісті жазба жаңартылады.

### 7. Архитектураның артықшылықтары

Үш деңгейлі архитектура OnlineStore жүйесіне келесі артықшылықтарды береді:

- Жүйе компоненттерінің міндеттері нақты бөлінеді.
- Интерфейсті бизнес-логикадан тәуелсіз өзгертуге мүмкіндік береді.
- Дерекқорға қол жеткізу бір компонент арқылы ұйымдастырылады.
- Жүйенің қауіпсіздігін қамтамасыз етуге көмектеседі.
- Қойма және жеткізу функцияларын бөлек дамытуға мүмкіндік береді.
- Жүйені кеңейтуді және техникалық қызмет көрсетуді жеңілдетеді.

### Қорытынды

OnlineStore ақпараттық жүйесінің үш деңгейлі архитектуралық диаграммасы пайдаланушылардың жүйемен өзара әрекеттесуін, негізгі бизнес-процестердің орындалуын және мәліметтердің SQL Server дерекқорында сақталуын сипаттайды.

Диаграммада клиент, әкімші, менеджер, қойма қызметкері және курьер рөлдері, пайдаланушы интерфейсі, қолданбалы логика модульдері, деректерге қол жеткізу компоненті, дерекқор және олардың арасындағы бағытталған байланыстар көрсетілген.

Ұсынылған архитектура интернет-дүкеннің тапсырыс беру, төлем тіркеу, қойма жұмысын ұйымдастыру және жеткізуді басқару процестерін жүйелі түрде жобалауға негіз болады.
